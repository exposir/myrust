Native UI

A window can show a user interface that MyRust draws itself instead of a web page. You write it in Rust with the ui module: there is no HTML, no JavaScript and no frontend build, and the window starts no WebView, so it opens at once and uses little memory. MyRust resolves the layout on the CPU, rasterizes the display list into a pixel buffer, and presents it through softbuffer; an optional gpu feature adds an offscreen wgpu renderer for supported geometry.

use std::cell::RefCell;
use std::rc::Rc;

use anyhow::Result;
use myrust_core::app::{App, WindowConfig, WindowContent};
use myrust_core::ui::{button, column, text, NativeUi};

// counter is the app's state.
struct Counter {
    n: i32,
}

fn main() -> Result<()> {
    let mut app = App::new("counter")?;
    let state = Rc::new(RefCell::new(Counter { n: 0 }));
    let view_state = Rc::clone(&state);

    // view builds the window's interface from the state, for every frame.
    let view = NativeUi::new(move |c| {
        let mut app = view_state.borrow_mut();
        column(c)
            .fill()
            .center()
            .gap(12.0)
            .children(|c| {
                text(c, &app.n.to_string()).font_size(40.0).bold();
                if button(c, "Increment").clicked {
                    app.n += 1;
                }
            });
    });

    app.on_ready(move |context| {
        context.create_window(WindowConfig {
            title: "Counter".to_string(),
            width: 320.0,
            height: 240.0,
            content: Some(WindowContent::NativeUi(view.clone())),
            ..WindowConfig::default()
        })?;
        Ok(())
    });
    app.run()
}

Reading the examples. The examples in these guides are parts of a view such as Counter: c is the view's &mut Context, and app the value of your own type that holds the state. A field such as app.volume is one you declare on that type, as Counter declares n; Views says more.

The counter example is a complete window, and the gallery shows the controls and layouts. There is no project template yet: copy the example crate or add myrust-core to your workspace.

One app can have windows of both kinds. Native UI suits tools, settings, inspectors and utilities, and apps that must start instantly; a web page suits rich documents, existing web code and anything that needs what only a browser has. Assistive technology does not see native UI yet: the view emits semantic nodes, but no platform accessibility bridge is connected (see Accessibility).

Status: Implemented exists in the current crate; Partial ships a subset; Not implemented has no API yet. Descriptions keep the reference behavior from MyGo, so the eventual surface is clear.
